# 06 · 측정으로 확인된 것 · 실패한 설계

**새 기능을 설계하기 전에 이 문서를 읽을 것.**
여기 적힌 실패는 전부 "그럴듯해 보였지만 측정하니 안 됐던" 것들이다.

---

## 1. 구조적 사실 셋

### ① 요구치는 문턱이다 → "강하게 만드는" 시너지는 원리적으로 약하다

요구치를 넘긴 순간 추가 접근점수는 초과분(여유 0.70 환산)으로만 남아 거의 무가치하다.
그래서 카드를 강화하는 조력 효과는 값이 안 나온다.
게다가 한 계층을 조력에 쓰면 그 계층을 못 뚫으므로 대가가 지나치게 크다.

### ② 조건을 만드는 행위 자체가 이미 벌점이다

BREACH 의 상태 변수는 거의 전부 *비용*이다.
경계를 올리는 것도, 같은 유형을 반복하는 것도 손해다.
따라서 "쌓아서 터뜨리는" 구조가 안 만들어진다.

성립하는 시너지는 **자기 계층을 정상적으로 뚫으면서 상태를 남기는 카드**뿐이다.
권한(축적 → 소비)이 유일하게 그 조건을 만족한다 (+1.3%p).

### ③ 덱 선택이 플레이 실력보다 두 배 중요하다

```
봇 사다리 상승폭   random→greedy +12.0 · →thrifty +36.4 · →assign +3.0 · →deep +0.7 · →counter +3.2
기초 습득 이후 플레이 실력 폭     6.9%p
표적별 전용 덱의 홈 어드밴티지   13.6%p
```

"요구치만 넘기지 말고 흔적을 보라"는 단 하나의 교훈이 실력의 84% 를 차지한다.
그 위로는 여지가 적다. **깊이는 덱 구성에 있다.**

## 2. 실패한 설계 — 조건부 효과 4종

덱빌딩에는 "혼자면 약하고 짝이 있으면 강한 카드"가 필요하다. 4종을 설계해 전부 실패했다.

| 설계 | 조건 | 시너지 |
|---|---|---|
| 폭주 | 경계가 높을수록 강해짐 | −4.7%p |
| 연쇄 | 여유를 태워 접근으로 | 0.0%p |
| 연계 | 같은 유형 연속 | −0.4%p |
| 준비 | 다음 카드를 강화 / 조용하게 | −13.0 ~ −1.3%p |

살아남은 것은 **폭주** 하나다. 시너지는 없지만 "시끄럽게 밀어붙이는 빌드"의 보상으로 단독 성립한다.

## 3. 세 번 고쳐서 살린 효과들

### 백도어 — 네 번째에 성공

| 시도 | 사용률 | 왜 죽었나 |
|---|---|---|
| 카드 회수 | 14.0% | 손패가 이미 계층+4 라 "카드 한 장 더"에 값이 없다 |
| 다음 계층 요구치 감면 | 21% | **여유(SLACK)와 하는 일이 같다.** 여유는 공짜로 생긴다 |
| 다음 계층 소음 감면 | 19~31% | **은폐·위장막과 같은 니치**를 두고 겹친다 |
| **요구치 판정 우회** | 상대 1.03 | 아무도 안 가진 레버 |

여기서 또 배웠다: **요구치를 건너뛰면 스탯이 무의미해지므로 스탯 예산으로는 가격을 매길 수 없다.**
비용 6~20, 배수 0.35~0.50 어디서도 수치가 안 움직였다. 흔적 쪽(+26)에 붙여서야 균형이 잡혔다.

### 적응 — 축을 두 번 옮김

| 시도 | 사용률 | 왜 죽었나 |
|---|---|---|
| 저항 무시 | 19.6% | 손패가 크면 다른 유형을 내면 그만이다 |
| 저항 정화 | 14.9% | **저항이 문제가 되는 상황 자체가 드물다** (상한 도달 13.9%) |
| **최고 스탯을 주스탯으로 (morph)** | 92~98% | 스탯 축으로 옮기니 살았다 |

### 정찰 — 장비와 겹쳤다

능동 대응 무효화는 **분석기 장비가 공짜로 해주는 일**이라 카드 슬롯을 쓸 이유가 없었다 (8.4%).
"미리 훑어본다"를 여유 선지급으로 재해석해서 살렸다 (92.5%).

### 사이드채널 — 자기 모순

소음 0 인데 은폐(소음을 0 으로 만드는 효과)를 달고 있었다.
효과 비용 6 을 허공에 쓴 데다, 소음이 예산을 사는 구조에서 소음 0 은 예산도 못 받는다.
12종 중 최약체(27.5%)였다. 소음 2 로 바꿔 예산을 받고 은폐가 그걸 지우게 했다.

**네 사례 다 수치가 아니라 "효과가 답하는 질문"이 틀렸던 것이다.**

## 6. 포팅 함정 5건 (JS → Dart)

| # | 함정 | 증상 |
|---|---|---|
| 1 | `Math.imul` | Dart 웹은 int 가 double — 2^53 넘으면 정밀도 소실 |
| 2 | `Math.round` 방향 | JS 는 절반을 위로, Dart 는 0에서 먼 쪽으로 |
| 3 | `List.sort` 불안정 | JS 는 ES2019부터 안정 보장 |
| 4 | 계획 봇의 비용식 2종을 **하나로 합침** | 원본에서 초기 배정과 thrifty 는 다른 식 |
| 5 | `bestDelta` 에서 `- slack - slackGain` 누락 | 장비 판단이 갈림 |

4·5 는 **포팅하면서 코드를 "개선"해서** 생겼다.
5번을 고칠 때는 원본을 안 보고 추측해서 항을 더 지우기까지 했다.

> **포팅의 원칙: 번역하되 개선하지 않는다.**
> 개선하고 싶으면 JS 쪽을 고치고 골든을 다시 뽑는다.

## 7. 카드 한 장씩은 옳은데 배치가 틀린 경우 (2026-08-05)

카드 풀 30 → 60종 확충의 1차 배치. **효과 커버리지부터 메우자**는 판단으로
효과 카드만 9장 넣었다 (소거 1→3, 과부하 1→3, 나머지 2→3).

카드 하나하나는 규칙을 지켰다 — 예산에서 파생, 효과별 작동 조건 존중
(은폐는 소음 3, 적응은 EVA 75 특화), 유형 편중까지 같이 해소해 우회 12/정공 9/강습 9 →
정공 14/우회 13/강습 12 로 고르게 만들었다.

**그런데 전부 실패했다.**

```
파레토 검사   개선 2 · 악화 3  → 불통과
  M1  성공률            52.9% → 46.7%   (n=8000, CI ±1.1%p — 노이즈 아님)
  M2  결정 레버리지        334 → 283
  M3′ 원형별 최대 사용률  40.2% → 33.3%   (문턱까지 3.3%p)

감사          전항목 통과 → 9건 실패
```

### 원인 — 효과는 스탯 예산을 산다

```
효과 카드 비율     40% (12/30)  →  54% (21/39)
풀 평균 스탯합    136.3         →  134.5

새 9장 평균          128.2
기존 무효과 18장     140.0      ← 11.8 낮다
```

`EFFECT_COST` 가 과부하 20, 정찰 12, 소거 10 이다. 효과 카드는 그만큼 스탯이 깎인다.
효과 카드만 모으면 **풀 전체의 평균 파워가 내려가고**, 무작위 덱으로 재는 주 지표가
통째로 하락한다. 감사 실패 9건 중 8건이 그 파생이었다 —
「승산 없는 덱이 없음」 9.8%, 「장비 없이도 승산」 17.0%, 「연속 런 완주율」 5.8%,
심지어 점수 분산이 줄어 `OVERFLOW_KEEP` 이 사문화 판정까지 받았다.

### 배운 것

> **배치를 "구멍 종류별"로 자르면 배치마다 구성비가 쏠린다.**
> 효과·권한·특화를 순서대로 넣는 계획은 매 배치가 한쪽으로 기운다.
> 배치는 **최종 목표 구성비를 그대로 축소한 세로 조각**이어야 한다 (3 효과 : 7 무효과).

한 가지 더: 이때 "다음 배치에서 회복될 것"이라는 유혹이 있었다.
§5 의 측정 오류 14건이 대부분 그 논리였으므로 **되돌리고 기록만 남겼다.**

## 8. M3′ 를 갈아치우려다 실패한 기록 (2026-08-05)

구성비를 맞춘 2차 배치(3 효과 : 7 무효과, 30 → 40종)에서 M3′ 만 목표를 벗어났다.
원인을 파보니 카드 한 장(`stack_smash` 26.3%)이었고, 소음 3 → 2 로 고치니 44.0% 로 살았다.

이때 M3′ 자체를 의심할 근거가 두 개 있었다.

**① M3′ 는 `min over cards` 라 풀이 커지면 순위통계로 내려간다.** 이건 측정으로 확인됐다:

```
        n    최저    p10    p25   중앙    p75    최고
30종     30  40.2%  59.9%  69.5%  89.5%  98.2% 100.0%
40종     40  36.6%  54.5%  69.7%  88.3%  98.0% 100.0%
                −3.6         +0.2   −1.2
```

분포는 안 움직이고 **꼬리만 길어졌다.** 카드가 나빠진 게 아니라 최솟값을 더 많이 뽑은 것이다.

**② M3′ 는 하한만 있고 상한이 없다.** 실측: 순수 스탯 카드 `cold_boot` 98.7% 통과,
조건부 카드 `stack_smash` 44.0%. 덱빌더에서 조건부가 목표인데 지표는 반대를 선호한다.

### 그래서 대체 지표를 만들었고 — 틀렸다

`sim/analysis/adoption.mjs`: 원형별 챔피언 덱의 한 슬롯을 비우고 전 카드를 넣어 순위를 매긴다.
순위는 풀 크기에 자동으로 스케일되고 양쪽 꼬리를 다 본다. 그럴듯했다.

**정답이 붙은 사례로 검증하니 반대로 나왔다:**

```
stack_smash 소음3 (알려진 나쁨)  최고순위  7/40  → 건강
stack_smash 소음2 (알려진 좋음)  최고순위 15/40  → 건강
```

이유는 이 저장소가 §03 §2 에 이미 적어둔 함정이었다 —
**"카드 하나를 대조 덱에 넣어 재면 대조 덱이 흔적을 흡수해 과소평가된다."**
챔피언 덱은 최적화돼 있어 조용하다. 거기 시끄러운 카드 한 장을 끼우면 나머지 11장이
소음 여유를 흡수해 **소음 비용이 안 보인다.** 소음이 원인인 실패를, 소음이 안 보이는 자로 잰 것이다.

### 배운 것

> **M3′ 가 무작위 덱을 쓰는 건 결함이 아니라 이유였다.**
> 무작위 12장 덱은 시끄러워서 소음 비용이 그대로 드러난다. 최적 덱은 그걸 숨긴다.

②(상한 없음)는 여전히 유효한 지적이지만 **새 지표가 필요하지 않다** —
자동 채용 카드가 늘면 상위 덱이 수렴하므로 **M8′(상위 8덱 겹침)가 덱 단위에서 이미 잡는다.**
실측 23.1% 로 수렴 징후가 없다. 카드 단위 상한을 새로 만들면 중복이다.

`adoption.mjs` 는 게이트에서 내리고 **빌드 차별화 진단** 용도로만 남겼다
(`spread` = 원형 간 순위 폭. `cred_harvest` 는 exchange 1위 / telecom 39위).
그 파일에 게이트 함수를 다시 만들지 말 것 — 같은 실수를 두 번 하게 된다.

## 9. 콘텐츠가 늘면 **측정 도구부터 낡는다** (2026-08-05)

카드 풀을 30 → 50종으로 늘리는 동안 검사 셋이 깨졌다. 셋 다 **밸런스가 아니라 측정**이
문제였고, 셋 다 **30종에 맞춰 만들어져 풀이 커지자 조용히 무너진** 것이었다.

| 무너진 것 | 증상 | 원인 |
|---|---|---|
| `auditC #102` 소음 빌드 | 소음2.0 덱만 13.6% 로 함몰 | 같은 소음 카드가 12장을 넘자 **균질 덱**이 됨. 동점은 `balance.json` 삽입 순서로 깨짐 (순서만 섞어도 17%p 변동) |
| `M3′` 최대 사용률 | 40.2% → 36.6% | `min over cards` 라 표본이 늘면 **순위통계로** 내려감. 중앙값은 −1.2%p 뿐 |
| `M10` 홈 어드밴티지 | 18.9% → 5.4% (문턱 8%) | 챔피언을 "무작위 40개 중 최고"로 뽑는데 탐색 공간이 `C(50,12)/C(30,12)` ≈ **10배**가 됨 |

M10 은 특히 위험했다 — **차별화가 무너졌다고 오판**하게 만들었는데, 같은 풀을 탐욕으로
구성해 재니 정반대였다:

```
50종   무작위 40개 →  5.4% (1위 2/6)
       무작위 200개 → 12.6% (1위 3/6)
       탐욕 구성   → 22.9% (1위 6/6)   ← 실제로는 대폭 개선
```

배치가 스탯 특화 카드를 넣어 원형별 전용 덱의 재료를 만든 게 제대로 작동한 것이다.

### 배운 것

> **측정 도구에는 유효 범위가 있고, 콘텐츠가 그 범위를 넘어간다.**
> 밸런스 수치는 바꿀 때마다 재검증하면서, 측정 도구는 한 번 통과하면 영원히 맞다고
> 가정했다. 셋 다 그 가정 때문에 조용히 틀린 답을 내고 있었다.

**구분법:** 지표가 나빠지면 먼저 *같은 질문을 다른 방법으로* 재본다.
답이 크게 다르면 콘텐츠가 아니라 방법이 문제다. 셋 다 이 방법으로 잡았다 —
풀 순서 섞기(#102) · 분포 전체 보기(M3′) · 탐색 강도 올리기(M10).

**교정한 방법이 골대 옮기기가 아님을 보이는 법:** 정답이 알려진 지점에서 재현시킨다.
탐욕 M10 은 30종에서 문서 기준값(buildcheck 13.6%p)을 13.1% 로 재현했고,
무작위 40개 방식은 15.7% 로 못 맞췄다. 새 방법이 **더 정확한 것**이지 편한 것이 아니다.

## 10. 카드 풀의 상한 — 다양성과 「승산 없는 조합 없음」은 양립하지 않는다 (2026-08-05)

2차 배치(40 → 50종)는 구성비를 지키고 효과×유형 빈 칸을 채웠다.
**지표 10개를 전부 통과했다** — 개선 4 · 악화 1 (M2 −2.2%).

```
              40종     50종
M3′          36.6%   38.4%   ↑
M4           26.0%   26.6%   ↑
M8′          23.1%   17.1%   ↑ (겹침 감소)
M10          17.9%   22.9%   ↑  전용 덱 1위 6/6
```

**그런데 감사 3건이 막았다.** 셋 다 무작위 덱 강도 분산이다:

| # | 검사 | 40종 | 50종 | 기준 |
|---|---|---|---|---|
| 157 | 최약 툴킷 성공률 | 23.5% | 19.5% | >20% |
| 158 | 상하위 10% 격차 | 32.3% | 37.5% | <35%p |
| 242 | 승산 없는 툴킷 없음 | — | 18.5% | >20% |

### 원인이 아니었던 것 두 가지 (둘 다 재봤다)

**① 새 카드가 약해서?** 아니다. 최약 10덱 내 새 카드 비중 40.0%, 전체 비중 40.0% —
정확히 인구 비율이고, 최강 10덱에는 오히려 더 많다(44.2%).
그리고 격차가 벌어진 건 바닥(p10 −2.3)이 아니라 **천장(p90 +6.0)** 때문이다.

**② 난이도 보정으로 되나?** 안 된다. 기본 계층 요구치에 배율 k 를 곱어 스윕:

```
k     M1      최저    격차   #156<90 #157>20 #158<35
0.94  75.2%   28.0%  34.0%    ✗       ✓       ✓     M1 초과
1.00  53.6%   19.5%  37.5%    ✓       ✗       ✗     현재
1.03  41.2%   12.8%  34.0%    ✓       ✗       ✓     M1 미달
```

**어렵게 하면 바닥이 더 내려가고, 쉽게 하면 천장이 90%를 넘는다.**
M1 이 45~60% 인 구간에서 `#157` 을 만족시키는 k 가 없다.

**③ 스탯 형태가 극단적이라서?** 이것도 아니었다 — 오히려 반대였다.
특화 5장을 균일 쪽으로 섞어봤더니:

```
a=0.00 [80,30,30]  최저 19.5%  M1 53.6%  M10 22.9%
a=0.25 [72,34,34]  최저 16.5%  M1 50.7%  M10 22.0%
a=0.45 [65,38,38]  최저 14.0%  M1 48.8%  M10 21.6%
```

바닥이 **더 내려갔다.** 판정식이 `주스탯×0.65 + 나머지 평균×0.35` 라
특화 카드가 자기 계층에서 훨씬 높은 점수를 내고, 요구치가 문턱이라 그 손해가 증폭된다.
**완화하면 모든 덱이 약해진다.**

### 진짜 원인 — 트레이드오프다

바닥이 낮은 이유는 카드가 나빠서가 아니라 **풀이 다양해서**다.
무작위 12장을 50종에서 뽑으면 말이 안 되는 조합이 나올 확률이 커진다.
그리고 그 다양성이 M8′ 17.1% · M10 22.9% 를 만드는 바로 그것이다.

> **같은 원인이 한쪽 지표를 올리고 다른 쪽 검사를 깨뜨린다.**
> 앞의 §9 네 건과 달리 이건 측정 결함이 아니라 설계 축의 충돌이다.

### 남긴 결정

40종으로 되돌렸다. 60종 목표는 **산술(6×6+24)로 정한 숫자였고 측정이 뒷받침하지 않는다.**

카드를 더 넣으려면 `#157`·`#158` 이 **무작위 덱**을 재는 게 맞는지 먼저 정해야 한다 —
플레이어는 무작위 덱을 받지 않고 **고른다.** 풀이 30종일 때 무작위 12장은 풀의 40% 라
"아무 덱"에 가까웠지만, 50종에서는 24% 라 플레이어가 절대 만들지 않을 조합이 된다.

다만 **그 논증만으로 검사를 고치지 않았다.** §8 에서 같은 종류의 논리("무작위 덱은 틀린
population")를 폈다가 반증당했기 때문이다. 정답 사례를 먼저 확보한 뒤에 손댄다.
